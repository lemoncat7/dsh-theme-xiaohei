只加载页面和刷新，没有发送消息或修改业务配置。不能将此结果直接等同于公网代理或 Desktop 的耗时。

## 观察

- 三组首开/刷新侧栏就绪时间（毫秒）：16775/1238/1266、11645/5038/1120、2213/2025/1268。第三组开启 CPU 采样，有额外测量开销。
- 两个主要插件聚合脚本解码大小为 10584847 和 11332146 字节。直接 HTTP 响应传输大小接近原文大小；缓存有命中，也存在刷新后重传。尚未验证公网反代压缩与缓存策略。
- 安装的主题 client.js 约 6.5 MiB；主题生成的背景、角色图片以 base64 字符串打进脚本。不能单凭包大小断言它是全部瓶颈。
- 慢刷新样本首页 responseStart 为 3775 ms，后续插件下载约 100–140 ms。存在服务侧响应等待，不只是浏览器执行慢。
- 慢首开样本前端出现 2028 ms 和 4988 ms 长任务。快首开 CPU 样本包含模块 materialize、图片 onload、文本匹配及布局测量；聚合脚本归属仍需进一步拆分定位。
